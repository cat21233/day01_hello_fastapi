### 3.2 建表结果（`SHOW CREATE TABLE users`）

```sql
CREATE TABLE `users` (
  `id` int(11) NOT NULL AUTO_INCREMENT,

  `role` varchar(20) NOT NULL,
```

🔴 **关键点**：本机 `my.ini` 写着 `default-storage-engine=MyIsam`，而实际建出来是 **InnoDB**。

MyISAM 不支持事务，`commit` / `rollback` 会变成摆设。

## 4. 踩到的坑

### 坑 0：pymysql 强制用 latin1 编码密码 → 中文密码根本连不上

建应用账号时若照抄模板占位符，密码会是 `换成强密码` 这样的中文字面量。
**MySQL 侧建号成功、`mysql.exe` 能登**，但 Python 一连接就炸：

```
UnicodeEncodeError: 'latin-1' codec can't encode characters in position 0-4
```

根因在 `pymysql/connections.py`：

```python
self.password = self.password.encode("latin1")
```

**这是硬编码在驱动里的，URL 编码也绕不过**（`quote_plus` 产出的是 `%E6%8D%A2...`，解码回 str 后仍是中文）。
→ 结论：**数据库密码必须是 ASCII**。用 `Day01App#2026SQL` 之类即可。

### 坑 1：`/token` 收的是 JSON body，不是 form

```
POST data={'username':...,'password':...}  → 422 Unprocessable Entity
POST json={'username':...,'password':...}  → 200
```

`LoginRequest(BaseModel)` 走 Pydantic 校验，`data=` 发的是 `application/x-www-form-urlencoded`，
字段进不了 body → 422。**422 不是后端连不上库**，第一步就该看请求体格式。

### 坑 2：`SHOW TABLES` 前面必须先 `USE`

`mysql.exe -e "SHOW TABLES"` 在不指定库时查的是当前连接默认库，容易误判「表没建出来」。
正确写法：`-e "USE day01; SHOW TABLES;"` 或直接 `-D day01`。

### 坑 3：只看 SQLAlchemy 日志不算证据

日志写着 `"driver": "mysql+pymysql"` 只说明配置读到了，**不说明数据落进了 MySQL**。
必须用 `mysql.exe` 这个「第二个客户端」去查——这也是跨进程排除单点幻觉的标准手法。

### 坑 4：密码里的 `#` 必须 URL 编码

`DATABASE_URL=mysql+pymysql://user:Day01App#2026SQL@host/db` 会解析失败——
`#` 在 URL 里是 fragment 分隔符，之后的内容全被丢掉。
必须写成 `Day01App%232026SQL`。同理 `@` → `%40`、`:` → `%3A`、`/` → `%2F`。

## 4.5 最小权限账号（安全加固）

| 项 | 内容 |
|---|---|
| 账号 | `day01_app@127.0.0.1` |
| 授权 | `GRANT SELECT, INSERT, UPDATE, DELETE ON day01.*` |
| 未授予 | `DROP` / `CREATE` / `ALTER` / `GRANT` |

权限边界实测（用应用账号执行）：

| 探测 SQL | 预期 | 实测 |
|---|---|---|
| `DROP TABLE users` | 拒绝 | ✅ `1142 DROP command denied` |
| `CREATE TABLE t_probe` | 拒绝 | ✅ `1142 CREATE command denied` |
| `SELECT COUNT(*) FROM users` | 成功 | ✅ 返回 2 |
| `SELECT COUNT(*) FROM mysql.user` | 拒绝 | ✅ `1142 SELECT command denied` |

⚠️ **副作用（必须知道）**：应用账号没有 `CREATE`，所以 **`init_db()` 的 `create_all` 跑不动**。
表结构变更必须由管理员账号执行（后续用 Alembic 迁移文件跑）。这是「最小权限」的正常代价——
生产环境本来就不该让应用进程持有 DDL 权限。

用该账号端到端验证：`db_init` / `db_seed inserted=0` / 登录 **HTTP 200** / `app.db` mtime 不变。

---

## 6. 一句话结论

`SQLite → MySQL` 只动了**两行配置 + 一行依赖**，业务代码零改动，代价是引入了一个必须独立部署、必须运维的外部服务。
这个交换值不值，取决于你要不要「多进程并发写 + 独立部署 + 备份/主从」——而不是「SQLite 不够专业」。
