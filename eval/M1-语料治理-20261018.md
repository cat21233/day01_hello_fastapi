## 为什么这次不是自欺欺人

### ① 控制变量：旧基线逐位复现

把旧向量（`split_embeddings.backup.json`）灌进临时集合 `baseline110`（110 块），用**同一份 20 题**跑：

```
[FAIL] q05 / q07 / q11 / q20
recall@1 = 0.65    recall@3 = 0.80    recall@5 = 0.90
```

与 10-16 记录的基线**一字不差**，失败题也完全一致。说明评测脚本、模型、执行环境都没有漂移，`day020` 的提升不是环境变化带来的。

### ② 排除「块数变多所以更容易命中」

110 → 144 块，Top-1 的**随机**命中概率从 `1/110 = 0.91%` 降到 `1/144 = 0.69%`。
块数增加使随机命中率**下降**，因此 `0.65 → 0.95` 不可能由候选变多解释。

## 改了什么

只改了 3 个文件，各加一段模块 docstring，原有代码一行未动。

- `routers/limits.py` —— 原文件**仅 4 行代码、零注释**（只有 `Limiter(key_func=get_remote_address)`）。补入「限流 / 防刷 / 高频爬取 / 按 IP / 429」等语义。
- `routers/stream.py` —— 原有注释只有「逐字符」「流式」，补入「一个字一个字往外冒 / 打字机效果」。
- `routers/auth.py` —— 补入「访问凭证 / 30 分钟 / 长期不用重新登录 / refresh token 7 天 / role 区分权限」。

## 副作用（诚实记录）

**q18「切换模型厂商要改很多地方吗？」从 PASS 变成 FAIL。**

原因不是 llm.py 变了（它一个字没改），而是 `auth.py` 开头插入 docstring 后，**全文按 `chunk_size=200` 重新切块，块边界整体位移**。新的第 1 名是 auth.py 的「改库里的 role 立刻生效，不用重新发 token」（cos=0.4942），llm.py 退到第 5（cos=0.4691）。

净账：**修 4 题、新增 1 题**。

这条副作用本身是重要结论：**语料治理不是单调改进，每补一个文件都会重排切块，必须重跑全量，盯住未治理文件相关的题是否掉分。**

## 工程注意（踩过的坑）

1. **`rag_store.ingest()` 是幂等的**（`rag_store.py:66`：`if col.count() > 0: return`）。改完 docstring 直接 ingest **静默无效**，必须先 `delete_collection` 或换集合名。
2. **`ingest` 读的不是实时文件**，是预计算好的 `split_embeddings.json`。链路是：`_probe_split`（分块+编码）→ `ingest`（写 Chroma）→ `run_baseline`（评测）。少跑第一步，改什么都不生效。
3. **`chunk_size=200` 会切断 docstring**。实测 auth.py 的 docstring 被切成两块（`…用了 HTTP` 处断开）。docstring 应控制在 150 字内，把关键词放在前 100 字。
4. **`.chroma_probe` 里有多个集合**（`day020` 和 `probe`）。删库只能 `delete_collection('day020')`，**不能整目录删**，否则连带删掉其他实验数据。

## 复现命令

```powershell
# 1) 重新分块 + 编码（会覆盖 split_embeddings.json）
python -m llm_service._probe_split

# 2) 删旧集合（ingest 幂等，不删等于没改）
python -c "from llm_service.rag_store import get_client; get_client().delete_collection('day020')"

# 3) 灌入新向量
python -c "from llm_service.rag_store import ingest; print(ingest(None, 'day020'))"

# 4) 评测
python eval/run_baseline.py
```
