# M1 rerank 实测报告（2026-10-16）

> 全部数字为亲手实测（`.venv` Python 3.12 + `sentence-transformers` 6.0.1 + CPU torch）。
> 评测集：`eval/retrieval_eval.jsonl` 20 题。库：Chroma `day020`，110 块。

## 二、主实验：池子大小扫描（dense 与 rerank 同池同口径）

| pool | dense @1 | dense @3 | dense @5 | rerank @1 | rerank @3 | rerank @5 |
|---|---|---|---|---|---|---|
| 5 | 0.65 | 0.80 | 0.90 | **0.75** | 0.80 | 0.90 |
| 10 | 0.65 | 0.80 | 0.90 | **0.75** | 0.80 | 0.85 |
| 20 | 0.65 | 0.80 | 0.90 | 0.65 | 0.80 | 0.80 |
| 30 | 0.65 | 0.80 | 0.90 | 0.65 | 0.75 | 0.80 |
| 50 | 0.65 | 0.80 | 0.90 | 0.65 | 0.75 | 0.75 |

**三条结论（全部实测）**：

1. **rerank 对 recall@3 零提升** —— 每个池子上限都是 0.80，池子开大还会掉到 0.75。
2. **池子越大越差**（@5：0.90 → 0.85 → 0.80 → 0.80 → 0.75）。候选越多，噪声越大，正确块被挤下去的机会越多。
3. **rerank 唯一的稳定收益是 recall@1**（0.65 → 0.75），且只在 **pool = 5 / 10** 时成立；**pool = 5 是唯一"只赚不赔"的配置**（@3/@5 与 dense 完全相同）。
4. dense 一列在所有 pool 下都相同 —— 这是**正确性自检**：pool 只影响 rerank 的候选集，不该动 dense 的前 k 名。相同即口径无误。

## 四、根因实验：reranker 为什么在代码语料上失灵

**单变量对照**（同一个模型、同一个 query，只改候选块的文本）：

| 候选块 | rerank 概率 |
|---|---|
| q05 的 query 与自身重复 | **+1.0000** |
| 英文正例（Paris / capital of France） | **+0.9998** |
| `limits.py` 原块 + **一行中文注释** | **+0.9929** |
| `limits.py` 原块（4 行代码、零注释） | **+0.0002** |
| `items.py` 的 CRUD 块 | +0.0000 |
| 无关中文（学生选课系统） | +0.0000 |
| 英文负例（mitochondria） | +0.0017 |

**结论**：模型没坏（自然语言判别几乎完美）。**它判的是"自然语言的相关性"，而我们的语料是裸代码。**

- 代码块里没有可判读的自然语言 → rerank 概率全部塌到 0.000 ~ 0.232 的噪声带
- 噪声带内排序不可靠 → q07 被从第 5 推到第 9，q12 从第 3 推到第 5
- 补一行中文描述 → 概率 0.0002 → 0.9929，**相差 5000 倍**

## 六、修正后的 M1 顺序（推翻先前"先 rerank"的建议）

先前判断"q07/q20 差榜首 0.01 cos → rerank 是确定性收益"**已被实测推翻**。真实瓶颈不在排序算法：

| 优先级 | 动作 | 依据 |
|---|---|---|
| **1** | **语料治理**：9 个 router 统一补模块级 docstring（一条与题目无关的通用规矩）→ 重建向量库 → 重测 | 补一行注释让 rerank 概率 ×5000、让 dense cos 0.40→0.58（名次 50→1）。**这是唯一能同时救 dense 和 rerank 的动作** |
| 2 | rerank 作为**放大器**接入，`pool = 5` | 唯一只赚不赔的配置，收益 = recall@1 0.65 → 0.75 |
| 3 | BM25 | 工程标配、面试必问，但对本题集 **确定性无效**（零词面重叠）；不要指望它抬指标 |

**一句话**：**指标不涨不是算法不够好，是语料不承载语义。** 排序算法只能在你给它的候选里挑，挑不出语料里没写的东西。

## 七、必须一起记下的口径

- **`pool` 是新的超参**，与 `n_results` 不是一回事：`pool` = 粗召回池大小，`n` = 最终返回条数。**报指标时必须同时报 pool**，否则就是又一次"口径差一点、数字说谎"。
- rerank 分数是 **Sigmoid 概率 [0,1]**，与 `cos`（`1 − d/2`，l2 空间）**量纲不同，不可跨模型比较**。只可用于**同一 query 内**候选之间排序。
