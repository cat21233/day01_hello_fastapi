## 二、本轮最重要的发现：抢位置是可复现的零和游戏

补 `llm.py` docstring **修好了 q18（名次 5 → 1）**，但同时把 **q02 从第 1 名挤到第 2 名**：

```
补 llm.py 后：
q18  切换模型厂商要改很多地方吗？   llm.py 名次 5 → 1   ✅
q02  哪个接口可以按名称模糊搜索商品？ items.py 名次 1 → 2  ❌（被 llm.py 顶掉）
```

两份 docstring 都含「接口」语义，向量空间里互相抢注意力。**所以「补一个 docstring = 净改进」这个假设是错的**，第 1 轮已有过一次证据（q18 被 auth.py 顶掉），本轮完整复现：**改一处 → 必须重跑全量**。

接着补 `items.py` docstring（题库里 4 道题指向它，却是唯一没治理的大户），q02 回到第 1，连带把 `recall@1` 从 0.95 推到 1.00。

## 四、暴露的 4 条脆弱测试 + 修法

改 docstring 后 `pytest` 直接红了 4 条，全部是 `tests/test_rag.py`：

| 测试 | 失败原因 | 修法 |
|---|---|---|
| `test_ingest_forward_slash` / `backslash` / `idempotent` | `AUTH_BLOCKS = 30` 硬编码，auth.py 现在切 37 块 | 常量改 37，注释写明「语料快照，改 auth.py 必须重量」 |
| `test_query_shape_and_score` | 钉死 `score ≈ 0.1422`、首条来源 `users.py`，全被语料重排打穿 | **改成与语料无关的方向判据**（见下） |
| `test_query_without_source_spans_files` | 断言「3 条结果跨 ≥2 文件」，那是检索质量差的副作用；auth.py 一治理，前 3 名全是 auth.py | 改判「问商品的事必须能在 items.py 找到」 |

### score 断言的替换逻辑

原来钉精确值 0.1422，理由是「区间判据抓不住方向写反」。方向判据其实可以做得更好——

用**相关问句 vs 无关问句的符号关系**，对语料改动免疫，且两种写反都致命：

```
score = 1 - d（正确）→ near = +0.4897, far = -0.3680   通过
score = d          → far = +1.368     → assert far < 0 挂
score = -d         → near = -0.5103   → assert near > 0 挂
```

**实测验证过（不是推演）**，两次改坏分别报出：

```
E  AssertionError: 无关问句得分应为负，实测 1.368
E  AssertionError: 相关问句得分应为正，实测 -0.5103
```

## 六、下一步
