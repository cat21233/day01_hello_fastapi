## 2. 两个口径 bug（都曾让数字说谎）

### bug 1：`n` 与切片不同步

`n=3 → 5` 时 `hit3 = any(g in want for g in got)` 实际在测 Top-5，标签却仍是 `recall@3`
→ 系统一字未改，分数从 **0.80 假涨到 0.90**。
修法：`got[:k]`。**改 n 必须同步改切片。**

### bug 2：`score` 不是相似度

`collection.metadata = None` → Chroma 用默认 **l2 空间**，归一化向量下 `d = 2 − 2·cos`。
实测同一对 (q05, `limits.py`)：手算 `cos = 0.4030`，Chroma 返回 `d = 1.1939 = 2 − 2×0.4030`。

→ 原来的 `score = 1 − d` 其实是 **`2·cos − 1`**（会出现负数），不是余弦相似度。
排序不受影响（单调变换），**但标签骗人**。

```python
L2_SPACE = True                    # 建库时没传 metadata → 默认 l2
def to_cos(d): return 1 - d/2 if L2_SPACE else 1 - d
```

⚠️ 若以后建库改成 `metadata={"hnsw:space": "cosine"}`，这里必须同步改成 `cos = 1 − d`。

## 4. 为什么 BM25 救不了 q05/q11

`limits.py` 全块文本（全库仅 1 块）：

```
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
```

- q05「怎么防止接口被人恶意刷？」→ 逐字命中 `{}`（空集）
- q11「同一个IP一直刷新会被拦吗？」→ 逐字命中 `{}`（空集）

**零词面重叠 → BM25 得分恒为 0。** 关键词检索只吃字面，吃不到就一点忙帮不上。

### 补注释判别实验

| q05 | 0.4030 | 50 | **0.5767** | **≈ 1** |
| q11 | 0.4068 | 75 | **0.5438** | **≈ 2** |

（新名次 = 全库中「cos 高于该值」的块数 + 1，由 110 条全量分数实算。）

## 5. ⚠️ 诚实边界

上面那行注释恰好用了 query 的词 → 这是 **teaching to the test**，直接照做等于把答案泄进语料。
合法做法只有两种：

- **(a)** 定一条**与题目无关**的通用规矩：9 个 router 统一补模块级 docstring（说明职责），再整体重测；
- **(b)** 承认 q05/q11 是**语料上限题**，只记录天花板，不为它改语料。

**真结论**：检索效果的上限由语料决定，**算法救不了没被写进语料的语义**。
