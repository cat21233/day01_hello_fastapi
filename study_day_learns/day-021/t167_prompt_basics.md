# t-167 Prompt 基础：三档约束强度对比实验

> 日期：2026-09-11 ｜ 模型：deepseek-chat ｜ 方法论：单变量对照（只改 prompt）

---

## 一、实验设置

同一段输入文本，同一模型，**唯一变量是 prompt 的约束强度**：

```python
TEXT = "张三，男，1998年出生，住在重庆市渝北区，职业是软件工程师。"
```

| 版本 | Prompt 设计 | 约束档位 |
|---|---|---|
| **A 版·裸问** | `从下面这段话里提取信息：` | 零约束 |
| **B 版·清晰指令** | A + 指定 5 个字段 + `输出格式为字段:值` | 明确格式 |
| **C 版·强制 JSON** | 字段清单（含类型）+ JSON 样例 + 3 条死规则 | 结构化 + 样例 |

---

## 二、结果对比

### A 版·裸问
```
提取的信息如下：
- 姓名：张三
- 性别：男
- 出生年份：1998年
- 住址：重庆市渝北区
- 职业：软件工程师
```

### B 版·清晰指令
```
姓名:张三
性别:男
出生年份:1998年
住址:重庆市渝北区
职业:软件工程师
```

### C 版·强制 JSON
```json
{"name": "张三", "gender": "男", "birth_year": 1998, "city": "重庆市", "job": "软件工程师"}
```
`json.loads()` → ✅ 解析成功

## 三、量化对比

| 维度 | A 版 | B 版 | C 版 |
|---|---|---|---|
| 前言/废话 | 有（「提取的信息如下：」） | 无 | 无 |
| 行前缀 | `- ` | 无 | 无 |
| 字段名 | 模型自定（中文） | 指定（中文） | 指定（英文固定） |
| 数值类型 | `1998年`（字符串） | `1998年`（字符串） | `1998`（整数 ✅） |
| 可直接 `json.loads` | ❌ | ❌ | ✅ |

## 四、结论（三条）

**① 约束越具体，输出越「可消费」——但核心差别不是好看不好看**

A 版输出其实挺整齐（deepseek 强），**但下游代码接不住**：带前言、带 `-`、中文冒号、字段名不可预测。B/C 的进步不是"更美观"，是**从「给人看」变成「给程序吃」**。

**② 示例（样例）的约束力 > 文字描述**

C 版给了一个 JSON 样例，模型直接照着形状输出——比用文字说"输出 JSON 格式"有效得多。这和第 ② 档（few-shot）同源：**画出来比说出来准**。

**③ 类型约束必须显式声明**

写了「整数（不要带"年"字）」，模型才输出 `1998`；不写就是 `"1998年"`。**不声明类型 = 下游 `+ 1` 直接报错**。

**④ 一个意外发现**：我预测 B 版还会带前言（A 版带了），**结果没有**。说明「明确指定输出格式」这个动作本身就有约束力，模型不会再多嘴加解释。

## 五、踩坑记录

### 坑 1：f-string 里写 JSON 示例 → `ValueError: Invalid format specifier`

```python
PROMPT_C = f"""...
{"name": "张三", "gender": "男"}      # ❌ f-string 里 { } 是表达式插槽
...
文本：{TEXT}"""
```

**报错机制**：f-string 读到 `{` 进入表达式模式 → 解析 `"name"` 为字符串 → 接着遇到 `:` → **冒号后面全部被当作「格式说明符」** → 拿一大段 JSON 去格式化 str → `ValueError: Invalid format specifier ... for object of type 'str'`

**两种解法**：

| 解法 | 写法 | 评价 |
|---|---|---|
| A. 双花括号转义 | `{{"name": "张三"}}` | 保留 f-string，但转义啰嗦 |
| **B. 去掉 f 前缀 + 拼接** | `...文本：""" + TEXT` | ✅ 推荐，无转义地狱 |

⚠️ **必须连动改**：去掉 `f` 后，原来靠 f-string 注入的 `{TEXT}` 会变成**字面文本**（输出 `{TEXT}` 四个字符给模型），所以那处要改成 `+ TEXT` 拼接。

### 坑 2：对照实验的版本不能互相覆盖

第一次写 B 版时，直接把 `PROMPT_A` 的内容改成了 B 版的内容 → **A 版原始 prompt 丢失，对照断裂**。
（同类错误复发：t-170 时曾把 prompt 焊死在函数内部。）

**铁律：所有版本必须同时存在于文件里，一次运行全部跑完。**

## 六、可复用的 Prompt 骨架（抽取类任务模板）

```
① 任务描述      → 说清干什么
② 字段要求      → 键名 + 类型（含"不要带单位"这类细节）
③ 输出示例      → 给模型模仿的靶子（★ 最有效的一块）
④ 死规则        → 只输出 XX / 不要解释 / 不要 ``` 包裹
⑤ 待处理文本    → 用 + 拼接，别用 f-string
```

## 七、格式约束的四档强度（延伸认知）

| 档 | 手段 | 强制力 | 状态 |
|---|---|---|---|
| ① | 文字描述 | 软 | 本实验用过 |
| ② | 给样例 | 中 | 本实验用过 |
