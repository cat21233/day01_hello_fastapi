# t-176 Few-shot vs Zero-shot 对照实验存档（2026-09-09）

## 实验设置（单变量对照）

| 控制项 | 值 |
|---|---|
| 模型 | `deepseek-chat`（与 t-170 同，A/B 同模型） |
| temperature | 0 |
| 任务 | 客服消息三分类：技术咨询 / 闲聊 / 投诉 |
| 输出约束 | 「只输出标签本身，不要任何解释」（约束类技巧） |
| 唯一变量 | 是否在 prompt 里加 3 个分类示例（EXAMPLES） |

- Few-shot 示例（沿用 t-176 挑选）：Depends/Query 提问→技术咨询；你是谁→闲聊；接口又500了→投诉
- Zero-shot = TASK + 测试句；Few-shot = TASK + EXAMPLES + 测试句（其余完全相同）

## 结果（3 句 × 2 版）

| 测试句 | Zero-shot | Few-shot | 期望 |
|---|---|---|---|
| ① 超时参数怎么配啊，配了三次都报错（情绪+技术提问） | 技术咨询 ✓ | 技术咨询 ✓ | 技术咨询 |
| ② 又报错了，我真的会谢，这破库文档也看不懂，浪费一下午（情绪+发泄，无提问） | 投诉 | 投诉 | 无 gold label（边界句） |
| ③ 付了钱功能用不了，再不解决就退款（纯投诉对照） | 投诉 ✓ | 投诉 ✓ | 投诉 |

## 结论

1. **few-shot 的价值与模型强度成反比**：deepseek-chat 上 zero-shot 全部扛住（句①未被情绪词带偏），示例无增量；对比 9-07 agnes-flash 上示例曾把句①从投诉拽回技术咨询——模型越弱，示例越是刚需；强模型上示例≈冗余保险。
2. **句②暴露的不是模型问题，是示例没画出这条边界**：投诉示例「又500了什么时候修好」=情绪+故障，句②形状相同（情绪+故障、无提问），模型按示例形状泛化判投诉，合理。想让它判技术咨询，该改的是示例（加一条"带情绪但核心在问怎么解决→技术咨询"），不是换模型。
3. **边界句先定 gold label 再评模型**：句②这类模糊样本人工标注本身就有分歧，生产做法是先攒人工标注集（如 10 条）再算准确率，否则"对错"无从谈起。

## 与 t-170 的方法论连接

- 两个实验同一套单变量对照法：同模型 + temperature=0，一次只动一个旋钮（t-170 动"是否要求推理"，t-176 动"是否给示例"）
- 两类技巧分工：CoT=扩展推理（管想得对）；输出约束/few-shot=稳定与格式（管答得稳、边界准）
