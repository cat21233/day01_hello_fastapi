## 二、概念预习（理解"为什么"，明天才写得出来）

### 概念 1：D8 只做了"认证"，D9 补上"鉴权"

回顾 D8 的口诀：

- **认证（authentication）** = 你是不是你 → 验签 → 失败 **401**
- **鉴权（authorization）** = 你能干什么 → 查权限 → 不足 **403**

D8 的 `/me` 只验证了"你登录了"（认证）。但**登录 ≠ 所有接口都能访问**——比如"删除用户"这种危险操作，普通用户不能做，只有 admin 能做。

**这就是角色权限（RBAC, Role-Based Access Control）**：

- 每个用户有一个 `role` 字段（比如 `"admin"` / `"user"`）
- 用户登录时，把 role 放进 JWT 的 payload
- 受保护接口检查 role，不是 admin → **403 Forbidden**

**一句话**：D8 是"进门要刷卡"（401），D9 是"卡里要写 VIP 才能进 VIP 室"（403）。

### 概念 2：角色字段放哪 + 怎么检查

**放哪**：JWT payload 里加一个键：

```python
payload = {
    "sub": username,
    "role": "admin",        # ← 新加的
    "exp": ...
}
```

**怎么检查**：写一个 `get_current_admin` 依赖，**套在 get_current_user 外面**（子依赖套路，D3 学过）：

```python
def get_current_admin(current_user = Depends(get_current_user)):
    if current_user["role"] != "admin":
        raise HTTPException(status_code=403, detail="需要管理员权限")
    return current_user
```

**关键认知**：`get_current_admin` 先走 `get_current_user`（认证），再查 role（鉴权）——**认证在前，鉴权在后**，一层套一层。

### 概念 3：Security —— Depends 的"进阶亲戚"

FastAPI 提供 `Security()`，用法和 `Depends()` 几乎一样，但**多一个能力：安全作用域（scopes）**：

```python
from fastapi.security import OAuth2PasswordBearer, SecurityScopes

oauth2_scheme = OAuth2PasswordBearer(
    tokenUrl="token",
    scopes={"me": "读取我的信息", "admin": "管理员操作"}   # 声明有哪些权限
)

async def get_current_user(
    security_scopes: SecurityScopes,          # 这个接口要求的权限
    token: str = Depends(oauth2_scheme)
):
    ...
```

**作用域（scope）** = 细粒度的权限标签（`"me"`、`"admin"`）。接口声明"我要 admin 权限"，依赖检查 token 里有没有这个 scope，没有 → 403。

**先不用纠结**：明天先用简单的"role 字段"实现角色分级（概念 2），Security 的 scopes 是进阶写法，看情况再上。

### 概念 4：token 刷新 —— 为什么需要 refresh token

D8 你签发的 access token 只有 30 分钟寿命。问题来了：**30 分钟一到，用户就得重新输密码登录**——体验极差。

**解决方案**：双 token 机制

- **access token**：短命（30 分钟），用来访问接口
- **refresh token**：长命（7 天），**只用来换新的 access token**，不能访问接口

```
access token 过期 → 拿 refresh token 调 /refresh 接口
                   → 服务端验证 refresh token → 签发新的 access token
                   → 用户无缝继续用，不用重新登录
```

**类比**：access token = 短期停车券（30 分钟）；refresh token = 月卡（7 天有效，随时去换新停车券）。

**安全点**：refresh token 长命所以更危险——必须**只在 /refresh 接口用**，泄漏了也换不了新 access token（除非同时有密钥）。

### 概念 5：整合 —— 把鉴权铺满 W1 项目

D8 只有 `/me` 一个受保护接口。D9 的目标：**让 W1 项目的核心接口都需要登录**：

- `POST /items/`（创建商品）→ 需要登录（Depends(get_current_user)）
- `DELETE /items/{id}`（删商品）→ 需要 admin 角色
- `GET /items/`（查商品）→ 可以公开（或登录）

**这就是真实项目的常态**：**公开接口 + 登录接口 + 管理员接口**三层，靠 Depends 组合控制。

## 四、环境坑提醒（避免重踩）

- 老规矩：`--reload` 不生效；uvicorn 手动重启
- **403 vs 401 别搞混**：未登录 → 401；登录了但权限不够 → 403（明天代码里会同时出现，注意看状态码）
- refresh token 也是 JWT（`jwt.encode/decode` 同一套），**就是 payload 里标记类型**：`{"type": "refresh", "sub": ...}`——用 type 字段区分是 access 还是 refresh
- 别把 SECRET_KEY 写死在代码里（真实项目放 .env）——明天试着自己把 SECRET_KEY 挪到 .env（config.py 你 D6 学过 pydantic-settings）
