## 二、第 1 关｜构建：换台干净机器能不能装出环境

**这一关在防什么**：本地能跑 ≠ 别人能跑。依赖装不上、环境变量缺失、路径写死，换台机器就崩。

### 2.1 冷构建

命令：

```bash
docker build --target runtime -t day01-hello-fastapi:local .
```

关键输出（节选）：

```text
[stage 1/3] base    —— COPY requirements.txt → pip install（只装生产依赖）
[stage 2/3] test    —— COPY requirements-dev.txt + tests/，不参与部署
[stage 3/3] runtime —— 只 COPY main.py config.py common/ routers/ llm_service/
```

判定：✅ —— 理由：三阶段分层是 2026-09-24 实测通过的（容器化三关）。分层顺序经得起推敲：**先 COPY 依赖清单再 `pip install`**，改代码只失效最后一层，不重装依赖。

### 2.2 镜像体积

| 镜像 | 体积 | 说明 |
|---|---|---|
| test | 约 480 MB | 含 pytest / coverage，**不部署** |
| runtime | 约 210 MB | 只含生产依赖 + 生产代码，**这个才部署** |

> `.dockerignore` 的作用在此显形：`.venv` 几百 MB、`models/` 92MB、`study_day_learns/` 全部排掉。
> 另有安全作用——`.env` 在第一优先级被排掉，即使将来有人误改成 `COPY . .`，API key 也不会进镜像。

## 四、第 3 关｜运行时冒烟：服务真能对外用吗

**本次验收环境**：本机 `uvicorn` + `cloudflared` 隧道打出的公网 HTTPS 地址
`https://compile-prove-reservations-without.trycloudflare.com`
（⚠️ 临时地址，进程结束即失效。**本记录的价值在于"公网链路实测"这件事本身可复现，不在于这个 URL 永久有效**。）

| 检查项 | 命令 | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| 服务存活（公网） | `curl <公网>/health` | 200 | `200` + `{"status":"ok","app_name":"我的FastAPI学习项目","uptime_seconds":107.1,"llm_provider":"deepseek","version":"0.1.0"}` | ✅ |
| 签发 JWT | `curl -X POST <公网>/token -d '{"username":"zihao","password":"123456"}'` | 200 + token | `200`，JWT 165 字符，payload 含 `role: admin` | ✅ |
| 无 token 删资源被拦 | `curl -X DELETE <公网>/items/999` | 401 | `401` | ✅ |
| 假 token 被拦 | 同上 + `Authorization: Bearer fake.token.here` | 401 | `401` | ✅ |
| 流式端点鉴权 | `curl <公网>/stream/protected` | 401 | `401` | ✅ |
| **SSE 逐帧穿透公网** | `curl -N <公网>/stream/greet?name=叶梓皓` | 逐帧到达 | **10 帧全到**（9 个 `data:` + `event: end`） | ✅ |
| 参数校验 | `curl <公网>/stream/greet`（缺 name） | 422 | `422` + `loc:["query","name"]` | ✅ |

**为什么这几条不能省**（每条各防一种翻车）：

- **服务存活** → 服务进程根本没起来（配置缺失 / 端口写死），页面一片空白
- **签发 JWT** → 鉴权链路整体不通，后面所有带 token 的测试都无从谈起
- **401 三连** → 只验"带 token 能过"是不够的：那证明不了拦截逻辑存在。**必须同时验"坏 token 被拒"**，否则一个永远返回 200 的空壳也能"通过"验收
- **SSE 逐帧** → 这是**最容易被公网代理吃掉**的一环。很多反向代理会把流式响应缓冲成一坨，最后一次性吐出——那样功能"看起来能用"，实际逐字效果没了。必须看首字节时间与总耗时的差值
- **参数校验 422** → 证明 pydantic 模型在真实网络请求上生效，不只是本地 TestClient 里的假象

### 4.1 SSE 逐帧的量化证据

```
首字节 1.454s / 总耗时 2.684s / HTTP 200
```

两者相差 **1.23 秒**——如果代理把响应缓冲了，这两个数字会几乎相同（都是一次性返回）。差值本身就是"逐帧推送"的证明。

帧序列实测：

```text
data: h
data: e
data: l
data: l
data: o
data: ,
data: 叶
data: 梓
data: 皓
event: end
data: done
```
